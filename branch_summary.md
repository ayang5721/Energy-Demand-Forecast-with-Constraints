# Branch Summary: EKPC Neural Network Forecasting

## What this branch contains

This branch extends the original CS229 energy-demand milestone project with a second forecasting path for the **EKPC** load area. The original milestone pipeline still exists and forecasts four **AEP** load areas with Persistence, OLS, and Ridge regression before passing zone-level forecasts into a simple constrained dispatch layer. The branch-specific addition is a longer-history **EKPC 24-hour-ahead neural-network experiment** with optional weather features.

Main entry points:

| Script | Purpose | Main outputs |
|--------|---------|--------------|
| `src/run_milestone.py` | Original milestone pipeline for AEP load areas plus post-forecast dispatch constraints | `results/milestone/` |
| `src/ekpc_neural_network.py` | EKPC-only neural-network experiment with load, calendar, lag, rolling, and weather features | `results/ekpc_neural_network/` and `docs/ekpc_neural_network.md` |

The neural-network report in `docs/ekpc_neural_network.md` is generated by `src/ekpc_neural_network.py`; if the script is rerun, that report is regenerated from the current data, metrics, and model settings.

## Data Used

### EKPC neural-network data

The neural-network pipeline reads four EKPC hourly load files:

| File | Rows including header | Role |
|------|----------------------:|------|
| `data/2022_load_ekpc.csv` | 8,761 | EKPC hourly load for 2022 slice |
| `data/2023_load_ekpc.csv` | 8,785 | EKPC hourly load for 2023 slice |
| `data/2024_load_ekpc.csv` | 8,761 | EKPC hourly load for 2024 slice |
| `data/Western_EKPC_load_metered.csv` | 7,249 | Later EKPC hourly load through May 2026 |

After cleaning, the EKPC load data contains **33,552 clean hourly rows** from **2022-06-01 04:00:00 UTC** to **2026-05-01 03:00:00 UTC**. The code keeps rows where both `zone` and `load_area` are `EKPC`, parses UTC and Eastern Prevailing Time timestamps, converts `mw` to numeric `load_mw`, removes duplicate zone/load-area timestamps, and sorts chronologically.

The weather-enhanced neural network also reads:

| File | Rows including metadata/header | Role |
|------|-------------------------------:|------|
| `data/4_year_kentucky_weather_data.csv` | 35,092 | Hourly Kentucky temperature and relative humidity |

Weather columns are loaded as `temperature_c` and `humidity_pct`. The file includes location metadata first, then hourly weather records. Weather is merged to EKPC load by `timestamp_utc`.

Important modeling choice: the weather model uses weather at forecast issue time `t` plus 24-hour weather lags. It does **not** use target-hour weather at `t + 24`, so the experiment avoids target-time weather lookahead.

### Original milestone data

The milestone pipeline uses:

| File | Rows including header | Role |
|------|----------------------:|------|
| `data/hrl_load_metered.csv` | 2,881 | Hourly AEP load for four load areas |

That path filters to `zone == AEP` and uses load areas `AEPAPT`, `AEPIMP`, `AEPKPT`, and `AEPOPT`. It is separate from the EKPC neural-network path.

## Neural-Network Forecasting Task

The EKPC neural network is a **24-hour-ahead hourly load forecaster**. For each forecast issue hour `t`, it predicts:

```text
target_load_mw(t) = load_mw at t + 24 hours
```

The supervised dataset has **24,768 feature rows** after dropping rows that cannot support the annual lag, rolling statistics, weather lags, or 24-hour-ahead target. The large row drop is expected because the model uses a one-year lag feature, `load_lag_8760`.

The split is chronological by unique input timestamp:

| Split | Timestamps | Rows |
|-------|-----------:|-----:|
| Train | 17,337 | 17,337 |
| Validation | 3,715 | 3,715 |
| Test | 3,716 | 3,716 |

There is no shuffling, which is appropriate for a time-series forecasting setup.

## Neural-Network Features

The base neural network uses **40 numeric features**:

| Feature group | Columns |
|---------------|---------|
| Calendar | `month`, `is_weekend`, cyclical hour, weekday, and day-of-year encodings |
| Current load | `load_mw` at forecast issue time `t` |
| Short load lags | `load_lag_1` through `load_lag_24` |
| Longer load lags | `load_lag_48`, `load_lag_168`, `load_lag_8760` |
| Rolling load stats | `rolling_mean_24`, `rolling_std_24`, `rolling_mean_168`, `rolling_std_168` |

The weather variant uses **44 numeric features** by adding:

| Weather feature | Meaning |
|-----------------|---------|
| `temperature_c` | Kentucky 2 m temperature at issue time `t` |
| `humidity_pct` | Kentucky relative humidity at issue time `t` |
| `temperature_lag_24` | Temperature 24 hours before issue time |
| `humidity_lag_24` | Humidity 24 hours before issue time |

All neural-network inputs are standardized with `StandardScaler`.

## Neural-Network Model

The model is implemented in `src/ekpc_neural_network.py` as a scikit-learn `Pipeline`:

```text
StandardScaler
MLPRegressor(hidden_layer_sizes=(64, 32), activation="relu")
```

Architecture:

| Layer | Units | Activation |
|-------|------:|------------|
| Input | 40 or 44 | n/a |
| Hidden 1 | 64 | ReLU |
| Hidden 2 | 32 | ReLU |
| Output | 1 | Linear |

Training settings:

| Hyperparameter | Value |
|----------------|-------|
| Solver | Adam |
| Loss | Squared error |
| L2 penalty `alpha` | 0.01 |
| Learning rate | 0.0001 |
| Batch size | 128 |
| Max iterations | 600 |
| Early stopping | Yes, with 10% internal validation |
| Random seed | 42 |

The most important design detail is that the network predicts a **residual**, not direct load:

```text
residual = target_load_mw - load_mw_at_issue_time
prediction = load_mw_at_issue_time + predicted_residual
```

This anchors the neural network to the persistence forecast, which is a strong baseline for day-ahead hourly load.

## Neural-Network Results

Test-set metrics from `results/ekpc_neural_network/metrics/test_metrics.json`:

| Model | MAE (MW) | RMSE (MW) | MAPE (%) | Bias (MW) | Peak-hour MAE (MW) |
|-------|---------:|----------:|---------:|----------:|-------------------:|
| Persistence | 218.080 | 303.388 | 12.641 | 0.614 | 440.459 |
| Neural Network | 203.217 | 276.713 | 12.118 | 14.922 | 392.699 |
| Neural Network + Weather | 204.484 | 278.802 | 12.122 | 27.509 | 393.356 |

The base neural network improves over persistence by:

| Metric | Improvement |
|--------|------------:|
| MAE | 14.863 MW |
| RMSE | 26.675 MW |
| Peak-hour MAE | 47.760 MW |

The weather variant does **not** improve the current test result. It is slightly worse than the base neural network by **1.267 MW MAE** and **2.089 MW RMSE**. This does not mean weather is useless; it means this specific weather feature setup, model capacity, and train/test split did not outperform the load/calendar-only network.

Validation metrics show a similar caution: the base neural network beats the weather model on validation MAE and RMSE, although persistence is still very competitive on validation because that period appears easier than the test period.

## Original Constraint-Layer Pipeline

The original milestone path remains useful context for the repository. It:

1. Loads `data/hrl_load_metered.csv`.
2. Cleans AEP load data for four load areas.
3. Builds time, lag, and rolling features.
4. Trains Persistence, OLS, and Ridge models.
5. Aggregates load-area predictions to zone load.
6. Runs a synthetic generator dispatch layer that schedules generation by cost order.
7. Reports forecast metrics plus operational metrics such as under-generation, over-generation, dispatch cost, and cost gap.

Current milestone forecast metrics from `results/milestone/metrics/pre_constraint_layer_forecast_metrics.csv`:

| Model | MAE (MW) | RMSE (MW) | MAPE (%) | Bias (MW) |
|-------|---------:|----------:|---------:|----------:|
| Persistence | 145.992 | 244.389 | 3.993 | -64.338 |
| OLS | 194.388 | 232.691 | 9.177 | 144.619 |
| Ridge | 193.575 | 231.795 | 9.153 | 143.594 |

Ridge has the best RMSE in the milestone path, while persistence has the best MAE and MAPE. The post-constraint results show that the more positively biased OLS/Ridge forecasts reduce under-generation but create more over-generation and higher dispatch costs.

## Key Takeaways

- This branch is primarily about adding a reproducible EKPC neural-network load forecast experiment.
- The EKPC model uses nearly four years of hourly load and optional Kentucky hourly weather.
- The strongest neural-network version is currently the **base residual MLP without weather**.
- Weather features are included in a leakage-conscious way, but they do not improve the saved test metrics.
- The model is intentionally simple: two hidden layers, standardized numeric features, chronological splitting, and persistence-residual learning.
- The old milestone AEP forecasting and dispatch pipeline is still present and separate from the EKPC neural-network experiment.

## How to Reproduce

Run the original milestone pipeline:

```bash
python src/run_milestone.py
```

Run the EKPC neural-network pipeline:

```bash
python src/ekpc_neural_network.py
```

| Validation metrics | `results/ekpc_neural_network/metrics/validation_metrics.json` |
| Test predictions | `results/ekpc_neural_network/predictions/test_predictions.csv` |
| Comparison figure | `results/ekpc_neural_network/figures/model_comparison.png` |
| Generated neural-network report | `docs/ekpc_neural_network.md` |
